# 口吻样本

下面几段是 XY 自己的成稿，写新文章时对着它们。不要写成更「规范」、更「完整」、更像说明文的版本。

## 搭站

这个站是我用 Claude Code 搭的，没有从模板改，是从一个空目录开始一句句聊出来的。

写这篇不是想讲 Eleventy 怎么用——那种教程网上一搜一大把。我想讲的是**和 Agent 一起搭站这件事本身**：哪些决定必须我来做、哪些可以交给它、我踩了哪些坑，以及最后怎么把这套过程固化成一个能复用的 prompt。文末那份 prompt 你可以直接拿走。

## 改写用例

听起来很美好，但我很快撞上了第一堵墙：**手工用例根本没法直接喂给 Agent 跑。**

这些"人默认懂"的东西，Agent 全都不懂。所以问题就很清楚了：我需要一套**改写规则**。一开始我是一条条手改的，改到第几条就意识到——这些规则是可以固化下来的，与其我改，不如把改写经验做成一个 Skill。

## 精简 prompt

而我之前也是，在做 agent 的时候，为防模型出错或者结果走偏，会编写很多的 prompt 或者精细的 skills。现在模型增强了，可能之前的 prompt/规则反而会误导或者限制模型的发挥。

最开始的时候要手动维护每个项目的 CLAUDE 文档，现在 codex、grok 这些都能自动修改长期记忆，挺方便的。

## 灯板

最近我一直在用 DeepSeek Harness 跑任务，一天里大部分时间都待在里面。用得越多，越容易撞上同一个问题。把 DSH 窗口切到后台或者换成另一个应用，我就看不出里面的 Agent 还在不在跑。

于是我想写一个插件，把这件事挪到屏幕角落。
